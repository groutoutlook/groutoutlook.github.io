    • Recap:
      • PCB drill file export (excellon default.)
    • Run: 
      kicad-cli pcb export gerbers .\FT32_F6C_26.kicad_pcb -o .\FT32_F6C_26-prod -l F.Cu --no-protel-ext # no final flags, it will output to `.gtl`.
kicad-cli pcb export drill .\FT32_F6C_26.kicad_pcb -o .\FT32_F6C_26-prod
kicad-cli pcb export glb .\FT32_F6C_26.kicad_pcb -o .\FT32_F6C_26-prod\FT32_F6C_26-prod.glb # export to binary gltf.
f3d .\FT32_F6C_26-prod\FT32_F6C_26-prod.glb # use `f3d` to open glb files easily.
    • Resolution:
      • PCB render image 
        $pcbName = (rvpa .\*.kicad_pcb)
$artifactName = (Split-Path $pcbName -Leaf) -replace "kicad_pcb","png"
kicad-cli pcb render $pcbName -o ".\production\$artifactName" --zoom 15 --pivot="'-36,0,0'" --rotate="'-45,0,-20'"
        • #alternative pcbnew 3D viewer.
          • Recite: Current 3D view can be saved to an image with File → Export Current View as PNG…​ or Export Current View as JPG…​, depending on the desired image format. Current view can also be copied to the clipboard using copy button, or Edit → Copy 3D Image. bind ctrl+alt+shift+c "Copy the current 3D image to clipboard". Combined with x/y/z viewport is pretty good.
          • Reason: This is the only solution to also render an image which has User.Drawing.
            • Pro: or additional layer toggling, color, etc... without meddle with cli. Flexible.
              • No need to manually copy from explorer to clipboard and send.
            • Con: well, cant automate this. No ray tracing for you as well.
              • No static filesystem path.
              • No transparent background.
              • GUI. I just prefer #cli in general.
              • Fuck now I realize It cant even detect solder mask properly... No drill as well.
