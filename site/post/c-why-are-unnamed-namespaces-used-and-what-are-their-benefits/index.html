c++ - Why are unnamed namespaces used and what are their benefits?

  • Recap:
  • Run: 
    namespace{ int a = 1;}
int a = 1;
  • Resolution: for making class/object static inside the compilation units. Kinda the same as static
    • improvement over static as they even allow making types translation-unit-local.
      • #compsci ODR : One Definition Rule
    • improve a bit of performance on desktop environment.
    • use a unnamed namespace for classes
      • e.g, you need a class that will only be defined in a .cpp file and used only within that file. You want to call it CModuleLock. If it is not in an unnamed namespace and some other .cpp file accidentially has another class CModuleLock not in an unnamed namespace you won't be able to link your program.
  • Reason:
  • Root: 7.13 — Unnamed and inline namespaces – Learn C++
  • Related:
    • inline namespaces
      • Useful for splitting stuff into multiple sub-namespaces that all look like one namespace, if you need to do that for some reason.
        • This is similar to writing using namespace inner in the outer namespace,
          • but without the DRY violation of writing the name of the inner namespace twice.
    • using is for aliasing type names, namespace is for aliasing namespaces.
    • Somehow I still kept misusing them, alias typename is using, alias namespace is namespace.
