    • Recap: visit branch on browser gh browse -b dev

        • gh browse -c=33326a8fa66bce6169de8bb6ecc4b550fe3e33ec
          • it's partial match from the initial, up to the 5th digit. it's the most stable behaviour.
          • short sha-1 is 7 hex digits. long one is 40 digits.
            • why does git use a cryptographic hash function? - stack overflow
      • run: gh browse -c="$(git rev-parse --short head)" on any repo which has updated remote.
        • has --short flag or not is actually fine, since gh accept all of it.
        • #powershell : gh browse -c="$((git rev-parse --short head).substring(0,5))"
          • if it's (0,4) ; could match on some small hash amounts of repo.
          • recommend use up to 5 in most case. even that is still too small.
          • it's convenient if you want a web viewer of those files inside browser.
