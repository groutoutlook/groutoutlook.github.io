  • Pipe | and ! in hx
    • Recap: this could pipe selections to e.g. numbat or bc or fend(#default now).
    • Run: alternatively it could list directory.. try :pipe . with ls.
    • Resolution: minimal config as possible, since piping is already slow.
      • Prefer to use :pipe|| only in selection(s). Other usage are quite noisy.
    • Reason:
      • Pro: other than bc usage to evaluate math expression inside editors:
        • I could use with ov or bat pager, press v to enter editor -> %|strip-ansi
          • it remove everything annoying about ansi code if you open from bat.
        • use with sed or awk to manipulate complex #string. scooter hasnt supported piping yet.
      • Con:
        • It couldnt be used with .ps1 scripts as long as I havent assoc them. Only .cmd
          • mostly because #nushell executed scripts like that.
          • which means I sometimes has to keep .cmd in my shims folder.
    • Root: need to evaluate math when editting lrc files
    • Recite: #doc:
      • ! == shell_insert_output Run shell command, inserting output before each selection
      • | == shell_pipe pipe into commands.
      • Alt+!: shell_append_output Run shell command, appending output after each selection
      • $: shell_keep_pipe Pipe each selection into shell command, keep selections where command returned 0
