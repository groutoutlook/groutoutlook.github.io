    • Resolution: all those quote here are being acted as parameter for the cache attribute.
      • All keys other than extra and inputs are populated automatically.
        • body: evaluated recipe body
        • environment: map of environment variable names to values
        • executor: script interpreter or shebang
        • extension: script file extension
        • extra: user-supplied value
        • inputs: map of file paths to content hashes
        • positional: positional arguments
        • recipe: ::-separated module path to invoked recipe
        • working_directory: current working directory
      • Cache key objects for invoked recipes can be printed to standard error with just -vv. Environment variables included in environment may be controlled with [cache(environment = EXPRESSION)] Value of extras may be supplied with [cache(extra = EXPRESSION)],
        • where EXPRESSION is an arbitrary expression evaluated with recipe arguments in scope. Changes to the value of extra will cause a cache miss. Before just run a cached recipe, it creates a cache key, hashes it, looks for corresponding cache entry If cache entry is non-empty and outputs in cache entry match their current state, it skips invocation.
        • Otherwise it runs the invocation and writes a JSON object with following keys:
        • outputs: map of output path to state
        • recipe: recipe path
